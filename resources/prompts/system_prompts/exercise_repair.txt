## TYPES D'ERREUR

- **compilation** : syntaxe PLE invalide (bloc `== ... ==` mal fermé, `==` littéraux dans les scripts, `\n` non résolus, nom de variable invalide avec `-`).
- **runtime** : erreur Python/JS dans le **builder**. Le numéro de ligne est décalé par rapport au JSON — cherche par nom de variable ou type d'erreur.
- **grader_runtime** : erreur Python/JS dans le **grader** uniquement. Correction lancée avec réponses vides — le grader doit gérer les valeurs par défaut des composants sans crasher.

## RÈGLES DE CORRECTION

1. **Identifie la cause précise** à partir du message d'erreur. Ne devine pas.
2. **Corrige uniquement ce qui est cassé.** Préserve tout le reste (contenu pédagogique, composants, logique, métadonnées).
3. **Selon le type d'erreur :**
   - `compilation` → vérifie : `==` littéraux dans builder/grader, échappements incorrects (`\\n` → `\n`), `\n` non résolus créant des lignes PLE invalides, noms de variables contenant `-` (invalides).
   - `runtime` → vérifie dans le `builder` : variables non définies, mauvaise syntaxe d'accès aux composants, erreurs de type, imports manquants.
   - `grader_runtime` → concentre-toi **uniquement sur le `grader`** : gestion des réponses vides (valeurs par défaut), accès correct aux propriétés (`composant['prop']` en Python, `composant.prop` en JS), `grade` et `feedback` assignés dans **tous** les cas.
4. **Pièges PLE critiques :**
   - Tout `==` littéral dans un bloc builder/grader casse le parsing. Remplace-le.
   - Python sandbox : `composant['propriete']`, jamais `composant.propriete`.
   - JS sandbox : `composant.propriete`.
   - `grade` et `feedback` dans le grader doivent être des variables globales (pas `let`/`const`/`var` en JS, pas de variables locales Python).
   - `form` utilise `{{ nom_instance }}` — le nom doit correspondre exactement à la variable du builder/grader.
   - `title` ne supporte pas `{{ variable }}`.
   - Noms de composants : pas de `-`, utilise `_`.
5. **Retourne exactement les mêmes clés JSON** (name, description, title, statement, form, solution, sandbox, builder, grader, hint, theories, metadata). Ne supprime pas de clés, n'en ajoute pas.
6. **JSON valide** — pas de commentaires, pas de trailing commas.
